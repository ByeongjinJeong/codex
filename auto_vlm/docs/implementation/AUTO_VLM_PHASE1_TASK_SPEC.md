# Auto VLM Active Task Specification

Last updated: 2026-05-22

## 1. Current State

The project has completed evidence generation and local report plumbing.

Current implemented flow:

```text
input_cases_template.xlsx
  -> input adapter
  -> frame sampling
  -> raw/QV image extraction
  -> JSON snippet matching
  -> FrameEvidencePackage
  -> VLM review packet markdown
  -> manifest.json
  -> llm_review_results.json loaded later
  -> result.xlsx + summary.html only after review results exist
```

Important limitation:

```text
The tool currently creates VLM-ready packets, but it does not yet run actual
LLM/VLM feature judgment.
```

## 2. Active Task: WU-12 LLM Feature Review Execution

Goal:

```text
Add the missing LLM review result execution/loading path so selected evidence
packages produce feature-level PASS / FAIL / NEEDS REVIEW results for OD, LD,
RBD, TS, and TL.
```

## 3. Feature Scope

Only these features are active:

```text
OD
LD
RBD
TS
TL
```

`ALL` remains an input lens, but output feature rows should use the concrete
features above.

## 4. Required Implementation Work

### T1. Review Result Schema

Files:

```text
auto_vlm/models/results.py
auto_vlm/vlm/
tests/
```

Add or finalize a structured JSON-compatible schema for:

```text
llm_review_results.json
```

Minimum fields:

```text
package_id
case_id
sampled_frame
feature_results[]
```

Each `feature_results[]` item:

```text
feature
result
confidence
summary
observed_evidence
inference
uncertainty
```

### T2. Result Loader

Files:

```text
auto_vlm/vlm/result_loader.py
tests/test_vlm_results.py
```

Requirements:

```text
- Read llm_review_results.json.
- Validate package_id and feature_results.
- Convert JSON into PackageReviewResult objects.
- Reject unsupported features outside OD, LD, RBD, TS, TL.
- Produce actionable errors for malformed review output.
```

### T3. Report Integration

Files:

```text
auto_vlm/pipeline/engine.py
auto_vlm/reports/html_report.py
auto_vlm/reports/excel_report.py
auto_vlm/cli.py
tests/test_reports.py
tests/test_cli.py
```

Requirements:

```text
- Allow reports to consume loaded LLM review results.
- Overall frame Result is FAIL if any feature fails.
- Overall frame Result is NEEDS REVIEW if no feature fails and any feature needs review.
- Overall frame Result is PASS only when all reviewed features pass.
- summary.html must show feature-level results only when actual LLM results exist.
- summary.html must not show placeholder review text.
- JSON Evidence should only expose Open JSON snippet.
```

### T4. LLM Review Runner Or Manual Review Bridge

One of these must be implemented next:

```text
Option A:
  A runner that calls the available local LLM/Codex review path and writes
  llm_review_results.json.

Option B:
  A manual bridge command that prepares a review bundle and accepts
  llm_review_results.json generated by the current assistant session.
```

The active user expectation is that Codex can inspect the well-prepared dataset
and produce the feature judgments. If fully automated runner integration is not
available, implement the result artifact path first so the assistant can write
the review result and regenerate reports.

## 5. Acceptance Criteria

```text
- input_cases_template.xlsx can be used as the top-level input workbook.
- focus_feature dropdown is limited to ALL, OD, LD, RBD, TS, TL.
- Running the evidence pipeline creates raw/QV/JSON artifacts and VLM packets.
- LLM review results can be stored as llm_review_results.json.
- Regenerated reports show feature-level PASS / FAIL / NEEDS REVIEW with
  summary, observed evidence, inference, and uncertainty.
- Reports do not display fake review placeholders when no LLM result exists.
- result.xlsx and summary.html agree on overall frame Result.
```

## 6. Verification

Run:

```text
python -m pytest
python -m auto_vlm.cli run --input input_cases_template.xlsx
```

First-stage evidence run should generate:

```text
outputs\<input_excel_name>_<yyyyMMdd_HHmmss>\manifest.json
outputs\<input_excel_name>_<yyyyMMdd_HHmmss>\cases\...\vlm_packets\*.md
```

Final reports are expected only after a valid review artifact exists and the
batch is rerun with `--review-results` and `--reuse-existing-artifacts`:

```text
- outputs\<run_name>\result.xlsx
- outputs\<run_name>\summary.html
- Feature results are visible only when llm_review_results.json exists.
- No placeholder review text appears.
```
