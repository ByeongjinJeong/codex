## 1. Plan Summary

The office-hours review is the right product anchor.

```text
Product shape:
  Frame Evidence Package Evaluator

Core job:
  Given a frame/context from ADAS vision output, collect the visible frame,
  nearby context, optional JSON snippet/summary, and metadata into a standard
  evidence package. A VLM tester then evaluates that package qualitatively.

Main principle:
  The VLM does not verify a Jira/customer issue claim.
  The VLM reviews frame evidence like a tester.
```

## 5. Engineering Review

### Architecture

```text
                 +-------------------------+
                 | Input Adapter           |
                 | Excel / JSON / CLI      |
                 +------------+------------+
                              |
                              v
          +---------------------------------------+
          | Normalized Evaluation Case            |
          | what should be evaluated              |
          +-------------------+-------------------+
                              |
                              v
                       +-------------+
                       | Sampler     |
                       | frame list  |
                       +------+------+
                              |
                              v
              +-------------------------------+
              | Evidence Builder              |
              | image/context/json packaging  |
              +---------------+---------------+
                              |
                              v
              +-------------------------------+
              | Frame Evidence Package        |
              | actual VLM/report input unit  |
              +---------------+---------------+
                              |
              +---------------+----------------+
              |                                |
              v                                v
       +---------------+                +--------------+
       | Report Writer |                | VLM Tester   |
       | xlsx/html     |                | optional P3  |
       +---------------+                +--------------+
```

### Component Boundaries

```text
Input Adapter
  Parses and validates source-specific input.
  Must not sample frames, extract images, summarize JSON, or call VLM.

Normalized Evaluation Case
  Adapter output.
  Describes requested evaluation: video path, sampling request, JSON dir,
  project type, focus_feature, and metadata.

Evidence Builder
  Core Phase 1 component.
  Converts sampled frames into center/context images, optional JSON artifacts,
  evidence_integrity, and Frame Evidence Package.

Frame Evidence Package
  VLM input unit and report row unit.
  The VLM must consume this, not raw Excel rows or raw Evaluation Cases.
```

### Data Flow

```text
Excel row
  -> ExcelAdapter.validate()
  -> ExcelAdapter.to_evaluation_case()
  -> Sampler.resolve_sampled_frames()
  -> VideoReader.extract_center_frame()
  -> VideoReader.extract_context()
  -> JsonMatcher.find_frame_json()
  -> JsonSummarizer.summarize_frame()
  -> EvidenceBuilder.build_package()
  -> ReportWriter.write_pre_vlm_report()
  -> VlmTester.evaluate_package()       # optional, Phase 3
  -> ReportWriter.update_vlm_results()
```

### Engineering Findings

```text
1. CRITICAL: Evaluation Case and Frame Evidence Package can be confused.
   Fix: define both schemas and enforce VLM input as package-only.

2. CRITICAL: evidence_integrity is needed before trusting VLM judgments.
   Fix: add explicit fields for JSON availability, frame offset suspicion,
   overlay sync suspicion, and module visibility ambiguity.

3. HIGH: JSON summary needs budget rules.
   Fix: compact summary goes into prompt; raw snippet is linked for audit.

4. MEDIUM: output paths must be deterministic.
   Fix: path should be derived from case_id and zero-padded frame number.

5. MEDIUM: Phase 1 should support no-VLM mode.
   Fix: evidence/report generation must complete without VLM credentials.
```

### Failure Modes Registry

```text
+-----+-------------------------------------+-----------------------------+--------------------------------------+
| ID  | Failure mode                        | User-visible result         | Required handling                    |
+-----+-------------------------------------+-----------------------------+--------------------------------------+
| F1  | missing video path                  | case cannot run             | tool_error row, continue batch       |
| F2  | unreadable video                    | no frames extracted         | decoder/open failure message         |
| F3  | invalid frame_list                  | wrong sampled frames        | adapter error with row/cell/fix      |
| F4  | frame index out of range            | missing evidence            | clamp/skip with warning              |
| F5  | JSON folder missing                 | image-only review           | json_available=false                 |
| F6  | frame JSON missing                  | weak evidence               | keep image evidence, record missing  |
| F7  | malformed JSON                      | no summary/snippet          | parse error, continue                |
| F8  | JSON/video frame offset             | false mismatch              | integrity flag, conservative result  |
| F9  | visualizer module disabled          | apparent false negative     | integrity flag, avoid overclaiming   |
| F10 | JSON exists but not drawn           | apparent visual mismatch    | separate visualizer/data ambiguity   |
| F11 | context extraction too slow          | batch unusable              | cache/reuse deterministic artifacts  |
| F12 | VLM invents JSON value              | false report                | prompt/eval/schema guardrail         |
| F13 | focus_feature hides other issue      | missed visible anomaly      | lens-not-blindfold policy            |
| F14 | report mixes SW and sync issue       | bad triage                  | separate judgment categories         |
+-----+-------------------------------------+-----------------------------+--------------------------------------+
```

Critical gaps:

```text
- F8/F9/F10 require evidence_integrity fields.
- F12 requires prompt/eval tests before VLM output is trusted.
```
